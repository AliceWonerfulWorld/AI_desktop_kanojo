# MVP-02 透明・常駐ウィンドウの技術検証

関連: [Issue #2](https://github.com/AliceWonerfulWorld/AI_desktop_kanojo/issues/2)

## 実装した操作

- 340×580 DIP の透明・枠なし・影なしウィンドウを主画面右下に配置。上部112 DIPを吹き出し、下部468 DIPを立ち絵に使う。吹き出しを下端基準で頭上に寄せ、小さな尻尾を付ける。作業領域を使い、タスクバーを避ける。
- オリジナルの SVG 仮キャラを表示。正式な立ち絵や差分表示は #3、PNG / Live2D の描画アダプターは後続タスク。トレイ PNG も自作で、新規依存や第三者素材は追加していない。
- キャラの左ボタンドラッグで移動。6 DIP 未満は移動しない。通常クリックの交流イベントは #6 で実装する。
- 右クリック / トレイメニューに「表示」「非表示」「常に手前に表示」「透明領域をクリック透過（試験機能）」「主画面の右下に戻す」「開発者ツール」「終了」を用意。キーボードでキャラにフォーカスした場合は Enter / Space / Shift+F10 でもメニューを開ける。
- 最前面とクリック透過はメニューのチェック項目で即時変更。初期値は最前面 ON、透過は Windows / macOS のみ ON。専用設定ウィンドウは #9、位置と設定の永続化は #8 の範囲で、この Issue ではセッション内のみ。
- ウィンドウを閉じる操作は非表示にする。トレイの「終了」でプロセスごと終了。二重起動は既存ウィンドウを再表示する。
- 非表示からの復旧と再起動時の表示はフォーカスを奪わない `showInactive()` を利用する。macOS では通常の `show` イベントが発生しないため、メニューの表示状態も明示管理する。

## 座標とドラッグ

Main で `screen.getCursorScreenPoint()` とウィンドウの座標を扱う。いずれも DIP であり、Renderer の `screenX` や物理ピクセルとの混用を避ける。カーソルの取得は左ボタンのドラッグ中のみ、16ms ごと。常時のポーリングやキーボード・画面内容の取得は行わない。

移動中はカーソルに近いディスプレイ、表示復帰時とディスプレイ変更時はウィンドウと最も重なるディスプレイの `workArea` 内に収める。負の原点も許容。取り外し、追加、DPI / 回転 / タスクバー変更で再補正する。極端に小さい作業領域ではウィンドウ寸法を縮小する。通常サイズに戻す場合は「主画面の右下に戻す」を選ぶ。

Pointer Capture でウィンドウ外のリリースを受け、pointerup / pointercancel / capture 喪失 / blur / ページ遷移 / 非表示 / 終了でドラッグを停止。イベント喪失への保険として30秒でも停止する。長いドラッグが停止した場合は一度ボタンを離してやり直す。

## 透明領域のクリック透過方式

1. CSS / ウィンドウ背景のアルファ透過で見た目を透明にする。
2. Renderer の `document.elementFromPoint()` と SVG の `pointer-events: visiblePainted` で、塗られたキャラの形状にヒットしたかを調べる。
3. 形状外では Main の `setIgnoreMouseEvents(true, { forward: true })` で OS にマウス入力を通す。
4. マウス移動だけを Renderer に転送し、キャラへ戻ると `setIgnoreMouseEvents(false)` に戻す。ドラッグ中は透過しない。
5. IPC は自分のメインフレームからの boolean だけ受理。任意チャンネル、座標、ファイルパスを Renderer に公開しない。

**結論:** CSS の透明化と OS のクリック透過は別々に設定する必要がある。今回の SVG 仮素材では輪郭の判別と OS API の切替を自動検証できた。別アプリへの実クリック到達はこの環境では未確認であり、下記の Windows 実機手順で評価する。試験機能として ON/OFF をトレイに残す。

公式資料:
- [Custom Window Interactions](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions): `setIgnoreMouseEvents` と Windows / macOS のマウス移動転送。
- [BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window): Windows では、管理者権限のウィンドウがアクティブな間に `forward` が一時停止する制限がある。
- [screen](https://www.electronjs.org/docs/latest/api/screen): DIP 座標、作業領域、ディスプレイ変更イベント。

### 制限・復旧方法

- ヒット判定から IPC の反映まで非同期であり、輪郭を素早く横切って即座にクリックした場合に取りこぼす可能性がある。OS のピクセル単位ヒットテストではない。
- PNG の透明部分や Live2D の WebGL canvas には SVG の方式をそのまま適用できない。#3 / #15 でアルファマスクや専用ヒット領域を検討する。
- Windows の管理者ウィンドウ上でキャラにマウス入力が戻らない場合は、トレイの透過チェックを外す。アプリを管理者として実行することを回避策にはしない。
- 透過 OFF の場合は透明な矩形全体がクリックを受ける。邪魔なら非表示にする。常にトレイから終了できる。
- `forward` による復帰を利用できない Linux は透過を無効にする。Wayland の座標取得や透過表示は検証対象外。
- DevTools を開くと透明表示の合成に影響する場合があるため自動では開かない。トレイから明示的に開く。
- トレイアイコンが Windows の隠れているインジケーターに入る場合は、その領域からメニューを開く。

## 自動検証結果（ローカル macOS）

- `npm run check`: ESLint / Prettier / 境界テスト5件 / TypeScript / Vite ビルド成功。
- `npm run test:smoke`: 実際の Electron を起動し、以下に成功。
  - contextIsolation / sandbox / Node API 非露出 / Preload 接続
  - 背景の CSS アルファ、透明余白とキャラの SVG ヒット判定
  - IPC によるマウス透過の切替、不正 payload の拒否、ドラッグ中の入力維持
  - 模擬カーソルで6 DIP 未満の無移動、閾値超過後の実ウィンドウ移動、終了後の停止
  - ネイティブメニュー処理による最前面解除、透過無効化、非表示/再表示、画面外からの復旧、close 後の復旧、終了

smoke は本物の OS ウィンドウを使うが、メニュー処理とカーソル座標の一部はプログラムから呼び出す。実マウスの入力経路、別アプリへのクリック到達、実ディスプレイの抜き差しを証明するテストではない。Windows / macOS の CI でも同じテストを実行する。

`npm run dev` の Main / Preload ビルドと Renderer サーバーの起動は成功。GUI 操作ツールは常駐ウィンドウへの接続でタイムアウトし、目視・実クリックによる確認は未完了。

## Windows 11 実機での再現手順（未実施）

1. `npm ci` → `npm run check` → `npm run test:smoke` → `npm run dev`。右下に枠や背景矩形のない仮キャラが表示され、トレイにアイコンがあることを確認。
2. キャラを左ドラッグし、画面の四辺で全体が作業領域内に収まることを確認。短いクリックで移動せず、ウィンドウ外で離しても追従が止まることを確認。
3. キャラを右クリックし、最前面を OFF/ON。別の通常ウィンドウを重ねて挙動を確認。
4. トレイから非表示 → 表示、位置リセット、終了を実行。表示復旧が作業中アプリのキーボードフォーカスを奪わないことを確認。Alt+F4 後もトレイから復旧できることを確認。
5. 背後に電卓等の安全な操作画面を置き、キャラの頭上や両脇の透明領域をクリック。背後のボタンが反応し、キャラ上では反応しないことを確認。透明部からキャラへ戻り、ドラッグと右クリックが復帰することも確認。
6. 透過 OFF/ON と素早い輪郭横断を試す。管理者権限のタスクマネージャーをアクティブにしても、トレイから透過 OFF・非表示・終了へ到達できることを確認。
7. 100% / 150% / 200% の表示倍率、主画面の左/上に置いた副画面、倍率の異なる2画面間の移動を試す。位置飛びや操作不能がないことを確認。
8. 副画面上にキャラを置いてから切断し、残った画面内に復旧することを確認。タスクバー位置や解像度変更でも確認。

Windows 実機での操作感・GPU合成・混在 DPI の最終判定はこの手順の結果を追記して行う。

## macOS（Apple Silicon）実機での手動確認（未完了）

作業中に更新された開発方針に合わせ、最初の手動受け入れは macOS で行う。上記 Windows 手順も将来の互換性検証用として残す。

1. `npm run dev` でキャラの背景にデスクトップが見え、メニューバーにトレイアイコンがあることを確認。
2. キャラをドラッグし、メニューバーと Dock を避けて移動でき、リリース後に追従が止まることを確認。
3. 右クリックとメニューバーのトレイで最前面 OFF/ON、非表示/表示、位置リセット、終了を確認。非表示後の Dock からの再選択でも復旧できることを確認。
4. 背後に電卓等を置き、キャラの両脇と頭上の透明部をクリックして背後が反応すること、キャラへ戻ってドラッグできることを確認。
5. 外部ディスプレイ、Retina / 非Retina、Dock の位置変更、ディスプレイ切断・スリープ復帰後の操作を確認。

ローカル macOS 上の自動テスト成功と、実マウスでの手動確認は区別する。手動確認結果を得るまで OS 越しの透過を実証済みとは扱わない。
