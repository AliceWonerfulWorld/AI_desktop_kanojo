# MVP-07 親密度・関係ステージ

> Issue #22更新: 小春5表情の実画像を統合済み。以下の「テスト素材では笑顔へ代替」はMVP-07時点の履歴で、現在の通常アプリはshy/affectionateの選定PNGを表示する。詳細は [小春統合検証](21-koharu-integration-validation.md)。

## 仕様

内部親密度は整数0〜100。`stranger` は0〜29、`familiar` は30〜69、`close` は70〜100。初期から明るく人懐っこく、親しくなると照れ笑い・控えめな甘えへ変化する。冷淡な初期応答、未起動の減点、交流を催促する表示、数値の常時表示は追加しない。

`RelationshipModel` はDOM・Electron・描画から独立する。受け付けたクリック交流だけで1点加算し、その後60秒間は追加加算しない。クリック反応の受付間隔（通常3秒、睡眠中15秒）とは別に制限する。最短でも30点に約29分、70点に約69分かかる。60秒はプロトタイプ調整値。

時計は単調時計を注入する。無操作・非表示・スリープ・未起動時間に自動加算や減点はなく、長時間空けても次の交流で最大1点。加算タイマーや過去の時間に対するまとめ加算はない。段階は毎回親密度から導出し、数値と段階を二重管理しない。

反応はクリック受付時の段階を使い、その反応の受付後に加算する。29→30、69→70に変わった場合、新段階のセリフは次の受け付けた反応から適用する。起動/復帰など既存の挨拶も、その時点の段階に合わせる。段階が変わっても追加の自発会話を出さない。

3段階×4行動×各3種の計36応答。初期段階の12応答は維持し、中盤で `shy`、closeで `affectionate` を使う。睡眠中は全段階で `sleepy` を維持し、起こさない。一時表情は既存の3秒で最新状態へ戻る。該当素材がない場合、同表情のidle→行動のsmile→idleのsmile→neutralの順で代替する。正式小春素材や4K原画の統合は本Issueで行わない。

## 保存境界

今回はセッション内のみ。再起動・Renderer再読み込みで0に戻る。未起動期間による減点ではなく、保存と復元が未実装のため。親密度・交流回数・受付間隔の再起動をまたぐ保持はMVP-08 (#8)で扱う。モデルは初期親密度を受け取り、保存層から復元できる形とする。新規IPC・依存パッケージなし。

## 自動検証（ローカル macOS）

- `npm run check`: ESLint / Prettier / 単体テスト49件 / 型チェック / ビルド成功。
- 親密度用6件で0/29/30/69/70/100、無効値、上限、固定時刻、1万回の連打、3秒ごとの交流、60秒境界、長期不在、減点なし、全36応答・12挨拶、段階変化、行動維持、代替画像を検証。
- `npm run test:styles`: 開発用の実アプリで固定親密度の設定、段階の導出、挨拶の切替、無効値の拒否を確認。開発/本番ともCSS検証成功。
- `npm run test:character`: 実PNGでfamiliarのshyとcloseのaffectionateがsmileと同じ画像へ代替され、要求した行動/表情の意味が維持されることを確認。既存の表示・復元・画像欠損・アルファ判定も成功。
- `npm run test:smoke`: 本番に `relationshipPreview` がないことを確認。既存のクリック/ドラッグ/連打/トレイ/最前面/透過/終了も成功。

## 手動確認（未実施）

1. `npm run dev` で起動。トレイの開発者ツールのConsoleで `behaviorPreview.pause()` を実行し、行動を固定する。
2. `await characterPreview.setState({ action: 'idle', expression: 'neutral' })` を実行。
3. `relationshipPreview.setAffection(0)`、`relationshipPreview.showGreeting()`。明るい初期挨拶を確認。DevToolsを閉じてキャラを短く左クリックし、初期反応を確認。
4. 同様に30と70を設定して挨拶とクリック反応を比較。現在のテスト素材では照れ/甘えは笑顔で代替されるが、セリフは異なる。連続する確認は通常3秒以上空ける。
5. `relationshipPreview.setAffection(29)` の後、クリックして `relationshipPreview.getState()` が `{ affection: 30, stage: 'familiar' }` となることを確認。次の反応から中盤口調になる。69→70も同様。
6. クリックを繰り返しても60秒以内の加算は1点まで。ドラッグ・透明部・右クリックでは加算しない。`setAffection` は開発専用でモデルと加算待ち時間を初期化するため、この確認の途中では呼ばない。
7. 読書/休憩/睡眠でも比較。睡眠は眠そうなままで、15秒間は再反応しない。`behaviorPreview.resume()` で通常進行に戻す。

`relationshipPreview` は開発ビルド専用で、`getState / setAffection / showGreeting` のみ。通常UIに数値や確認用ボタンは出さない。実マウスでの段階別の操作感、Retina/混在DPI、実スリープ、Windows実機は未確認。自動入力・模擬時計の結果とは区別する。
