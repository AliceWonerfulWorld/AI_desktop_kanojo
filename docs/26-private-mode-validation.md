# Issue #29 明示的な専用モードと通常復帰

## 実装範囲

成人向け専用入口は既存設定画面内の「成人向け専用モードの確認へ…」だけに置く。右クリック/トレイは既存の設定・表示・非表示・終了を維持し、専用入口や専用内容の通知は追加しない。PNG/生活行動/親密度を描画から分離する既存構成を保持する。

今回の専用画面は**全年齢のダミー表示のみ**。CG・成人向け文章・イベント再生・ログ・ギャラリーは追加しない。#30のイベントエンジン、#31の承認済み素材、#37の衣装切替を実装済みとは扱わない。ダミー左画像領域＋右説明欄は承認済みA配置の枠組みで、イベント本文・選択肢は #30。

## 入口・状態・入力

1. 設定ボタンから確認用ウィンドウを開く。設定ウィンドウは隠して再利用する。初期フォーカスはキャンセル、自己申告チェックは毎回OFF。
2. 「私は18歳以上です（自己申告）」をチェックし「専用モードを開く」を押す。自己申告は本人確認を保証しない。
3. Mainが専用webContents/mainFrame、現在のsession ID、確認段階、厳密な `accepted: true`、フォーカスを検証して専用へ遷移。日常PNGを隠し、既存の非表示停止機構で自律行動を一時停止する。
4. 戻る/キャンセル/Esc/OSの閉じるで専用ウィンドウを破棄し、入場前の日常表示を復元する。元から非表示/一時停止ならそのまま。強制的な挨拶や閲覧による親密度・交流回数加算はない。
5. 明示的な非表示・最小化、blur自動非表示ON、描画プロセス喪失や再読込では専用状態を解除し、日常も非表示にする。トレイの表示は通常PNGだけを再表示する。専用再入場には設定から新しい確認が必要。

日常表示へのOS通知は遅れて届く可能性があるため、復元元は実ウィンドウの表示状態を取得し、show/hide通知を現在の実状態と照合する。専用表示中に日常の遅延show通知が届いても専用を勝手に終了しない。

専用画面は不透明な矩形ウィンドウ。日常のクリック透過を継承せず、戻る・非表示・確認操作を背後へ通さない。キーはフォーカス中の画面だけで受ける。グローバルキー監視・画面監視・外部通信・新規依存なし。

## D5と保存

| 条件 | 専用画面の動作 |
| --- | --- |
| blur自動非表示ON（既定） | 専用ウィンドウを破棄・状態解除、自動再表示しない |
| blur自動非表示OFF | 表示維持、Mainのpausedをtrueにする。focusだけでは解除せず「明示的に再開する」で解除 |
| 確認画面のblur | ON/OFFによらず確認を取り消し、専用へ入れない |
| OSスリープ | ON/OFFによらず専用終了・通常モード。通常表示は元状態へ戻すがスリープ停止は解除しない |
| OS復帰 | 専用を再表示しない。既存の停止/非表示を尊重 |
| アプリ終了/再起動/クラッシュ後 | 許可も表示も保存しないため通常起動。表示可否は既存showOnStartup、停止は既存pausedに従う |

保存追加は `settings.privateHideOnBlur` のbooleanのみ。既存schema v1の未定義値をtrueで補い、明示falseは維持する。不正型は既存の破損検証・バックアップ/初期値復旧に委ねる。設定初期化でも既定ONに戻る。モード・自己申告・session・paused（専用進行用）は保存しない。日常設定の `settings.paused` とは別。

専用状態のrevisionで、遅いgetState応答が新しいpaused等を巻き戻さないようにする。#30ではこのMain所有のpausedと退出に再生処理を接続する。現在はイベントがなく、保存すべき中断位置は存在しない。D10のイベントID/ノード/ページの保存・一覧の「続きから」は #30/#31 へ引き渡す。再起動後に確認を省略しない境界だけを今回実装した。

## セキュリティと表示の限界

Main/Preload/Rendererを分離し、3画面ともnodeIntegration:false / contextIsolation:true / sandbox:true。専用Preloadには状態取得・限定コマンド・変更通知のみを公開し、記憶・ファイル・設定・ドラッグAPIを渡さない。設定Preloadの追加は入口APIだけ、日常Preloadに入口は追加しない。遷移/追加ウィンドウを拒否、ロード失敗/再読込/クラッシュでは閉じる。

タイトルは中立な「お話・イベント」、タスクバー表示を抑え、OSのキャプチャ除外API `setContentProtection(true)` を使用する。ただしOS/キャプチャ方式による制約があり、実OSのサムネイル/ウィンドウ切替残像/画面共有への完全な非露出を保証したものではない。実機QAは #34 で必要。本番の専用素材は今回存在せず、配布・販売承認や実CGのプライバシー検証完了を意味しない。
