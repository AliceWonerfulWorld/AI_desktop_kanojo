# MVP-05 時間帯・起動挨拶・時刻変更の検証

> MVP-06以降、復帰時の挨拶はアプリが可視かつフォーカス中の場合だけ表示し、クリック反応を優先する。[交流検証記録](19-interaction-validation.md) を参照。

## 時間帯と行動選択

`src/behavior/time-policy.ts` は端末の現地時刻（Date.getHours）で以下を選ぶ。

| 時間帯 | 時間 | idle | reading | resting | sleeping |
| --- | --- | --- | --- | --- | --- |
| morning | 06:00〜10:59 | 35 | 25 | 30 | 10 |
| daytime | 11:00〜17:59 | 25 | 40 | 30 | 5 |
| evening | 18:00〜22:59 | 30 | 25 | 30 | 15 |
| late-night | 23:00〜05:59 | 10 | 5 | 15 | 70 |

最初の行動もこの重みで選ぶ。初回を必ず idle に固定しない。重みは候補を絞った後に正規化するため、直前行動を除外した際の実確率は表の数値そのものではない。深夜のみ sleeping の連続を許可し、それ以外の同じ行動の連続は引き続き抑制する。

壁時計を選択のたびに読み直す。境界、タイムゾーン変更、時刻の大幅な前後変更があっても、進行中の行動は中断せず次回選択から反映する。時間帯のための常時ポーリングは追加しない。

行動の継続時間と吹き出しの寿命は単調時計で管理する。現地時刻を行動の経過時間に流用せず、時計を何年進めても遡らせても行動時間や交流時間を水増ししない。時間帯を利用しない既存の BehaviorEngine 利用者は従来どおり idle から開始する。

## 挨拶と初回判定

起動時に短い挨拶を5秒表示する。朝は「おはよう」、昼は「こんにちは」、夜は「こんばんは」、深夜は休息を促す文。初回だけ「はじめまして！」を添える。通常の自律遷移や時刻境界を跨ぐたびに挨拶を繰り返すことはしない。実際の台詞は描画/会話側にあり、行動エンジンに埋め込まない。

吹き出しは最大240px・固定 UI なし・pointer-events:none。表示中も、キャラのアルファヒットテストとドラッグを変えない。吹き出し部分は操作対象にはならず、背後へのクリック透過方針を維持する。古い表示タイマーは新しい挨拶を消さないよう世代で無効化する。

Main が userData 内に空の `welcome-seen.marker` を排他的に作成し、作成できたときだけ初回と判定する。既存なら通常挨拶、保存先が使用不能なら通常挨拶へ安全にフォールバックする。起動時刻・交流回数・未起動期間を保存したり推定したりしない。この小さな初回マーカーは #8 の設定/生活記憶保存とは別で、将来の保存形式へ統合可能。

Renderer への追加 API は、初回かどうかの boolean を読む `getLaunchInfo()` と、限定した suspend/resume 通知を購読する `onPowerState()` のみ。Main の読取ハンドラーは送信元ウィンドウとメインフレームを検証し、Preload は未知の通知値を破棄する。任意 IPC やファイルパスは公開しない。

## スリープと復帰

Electron Main の [powerMonitor の suspend / resume](https://www.electronjs.org/docs/latest/api/power-monitor/) を Preload 経由で通知する。

- suspend では、実行中だったエンジンだけを一時停止し、挨拶を隠す。
- resume では、自動停止した分だけを再開。ユーザーが先に一時停止/停止していた状態は勝手に解除しない。
- 重複通知は無視し、次回の行動選択ではその時点の現地時刻を使う。
- 可視状態での復帰時は現在の時間帯の通常挨拶を表示する。初回紹介を繰り返さない。
- pagehide / ウィンドウ終了時にタイマーと購読を解放する。

OS の停止直前に Renderer が通知を処理できる保証まではない。通知やタイマーが遅れた場合も既存の遅延処理で過去の行動を大量再生しない。OS未起動中・スリープ中の時間を交流記録へ加算する処理はない。累計稼働時間・交流回数の記録そのものは #8 の範囲。

## 開発用の模擬時刻

`npm run dev` → トレイの「開発者ツール」→ Renderer Console。

```js
timePreview.setLocalTime('2026-11-07T08:00:00')
timePreview.getState() // morning と重み、挨拶を確認

timePreview.setLocalTime('2026-11-07T12:00:00')
timePreview.setLocalTime('2026-11-07T20:00:00')
timePreview.setLocalTime('2026-11-07T01:00:00')

// 初期選択もすぐ試す場合（重み付きなので必ず睡眠になるわけではない）
behaviorPreview.stop()
behaviorPreview.start()
behaviorPreview.getState()

timePreview.reset() // 端末の現地時刻に戻す
```

模擬時刻は指定した日時に固定され、待っても模擬の壁時計は進まない。境界のテストでは 10:59 → 11:00 などを明示的に設定する。行動の残り時間は実際の単調時計で進み続ける。OS時計・タイムゾーン設定は変更しない。無効な文字列は例外として拒否し、直前の有効な設定を保持する。

プレビューで時刻を変更すると確認用にその時間帯の挨拶を表示する。本番の時刻変更時に毎回挨拶するという仕様ではない。`timePreview` は本番ビルドには存在しない。

## CIの起動挨拶チェック（2026-11-08）

Windows CIで、起動挨拶の文字列を読む時点で `''` となり `/はじめまして/` のassertが失敗するケースが報告された。挨拶は本来5秒で消えるため、その後の瞬間値から「一度も表示されなかった」とは判定できない。提示された実行の詳細タイミングは未特定だが、検証を5.5秒遅らせた一時スクリプトで旧assertと同じ空文字の失敗を再現した。

`scripts/smoke.cjs` はテストプロセス内だけで `desktop:launch` のハンドラーを包み、実ハンドラーの応答を返す前にRendererの吹き出しをMutationObserverで監視する。最初に実際に表示された非空テキストを保存し、その値が初回紹介を含むことを検証する。挨拶が一度も表示されなければ待機失敗、別の文なら文字列assert失敗となる。表示内容を注入せず、アプリの5秒タイマー・IPCの検証処理・初回マーカーを変更しない。監視は取得後に解除し、通常ランタイムへテストフックを追加しない。

`npm run test:smoke -- --slow-startup-check` は描画確認後に5.5秒待ち、表示実績に初回紹介が残る一方で実際の吹き出しは空文字かつhiddenであることを検証する。macOS/WindowsのCIに通常ケースと併せて追加。タイマー期限の厳密な単体検証は既存の模擬時計テストで維持する。

ローカルmacOSで `npm run check`（65単体テスト・型チェック・ビルド）、通常 `npm run test:smoke`、遅延ケースが成功。最終変更後のlint/format/diff検査も成功。実マウス・Windows実機は未実施。報告ログの `Temporary userData cleanup deferred: EPERM` はassert後の削除警告で、この変更の対象外。普段のセーブデータは一時userDataで分離する。
