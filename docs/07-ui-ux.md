## 1. 方針と参考ポイント

ユーザーが指定した記事は、特定のひとつのUIを模倣するための素材集ではなく、ノベルゲームの**表示・操作性・各種便利機能**を比較したもの。

今回、以下の考え方を参考にする。
- 「文字＋アイコン」で意味の伝わる操作ボタン
- テキストの可読性、表示位置と背景の分離
- ウィンドウサイズ・文字サイズの調整
- 前回の状態から再開するコンティニュー的UX（自動保存＋復元）
- 会話履歴（バックログ）と設定へのアクセス
- 音声導入時の音量調整、ボイス再生等（将来）
- イベント導入時のスキップ・オート・シーン回想（将来）

**重要:** 本作はノベルゲームではなくデスクトップ常駐が主軸。参考記事の機能をすべて実装するわけではない。

## 2. 情報設計：2モード

### A. 日常モード（デスクトップ常駐 / デフォルト）

```text
                    ┌───────────────────┐
                    │「今日は何を読もう？」│ ← 短い吹き出し（一定時間で消える）
                    └───────────────────┘
                         [2Dキャラ]
                  （透明背景・ドラッグ可能）

  操作: キャラクリック → セリフと表情
        右クリック → 小さなコンテキストメニュー
        トレイ → 表示/非表示、設定、終了
```

- キャラクター中心の透明ウィンドウ。常時のタイトルバー・固定ボタン群はなし。
- 通常の吹き出しは1〜2行程度を基本とし、周囲の作業領域を侵食しない。
- 任意の操作時だけ小さなメニューを開く。
- マウスドラッグと通常クリックは区別する。
- ユーザー操作・データ閲覧を強制しない。
- 無操作中にも自律生活のアニメーションが続く。
- 成人向け表現は突然ポップアップさせず、別モードへの明示的な操作を必須とする（販売版）。

### B. 交流・イベントモード（ノベルゲーム型 / 将来拡張）

```text
┌──────────────────────────────────────────────────┐
│                     [背景]                       │
│                [2Dキャラクター]                  │
│                                                  │
│  ┌───────────────────────────────────────────┐   │
│  │ キャラクター名                            │   │
│  │ セリフを読みやすい余白と行間で表示         │   │
│  │                                     ▼     │   │
│  └───────────────────────────────────────────┘   │
│     [ログ]   [設定]   [非表示]   [戻る]            │
└──────────────────────────────────────────────────┘
```

- 長文会話・特別イベントは常駐吹き出しではなく、専用ウィンドウで展開。
- 一般的なADV形式の「名前＋本文＋操作欄」を参考にする。
- 文字を立ち絵に重ねすぎない。可読性を優先する。
- 操作ボタンはアイコンだけに依存せず、ラベル/ツールチップを用意。
- ウィンドウを閉じても日常モードの生活・保存状態は継続。
- MVPの範囲では画面の**ワイヤーフレームのみ**を作る。フルシナリオエンジンは不要。

## 3. 画面・UI仕様の候補

| 機能・要素 | MVP | 将来 |
| --- | --- | --- |
| 透明背景にキャラだけ表示 | 必須 | 改善 |
| 日常吹き出し・表情変化 | 必須 | 種類追加 |
| 右クリックメニュー / トレイ操作 | 必須 | 操作追加 |
| 設定：前面表示・サイズ・自発会話 | 必須 | 詳細化 |
| 自動保存・再起動復元 | 必須 | 移行/バックアップ |
| ノベルゲーム型のイベント画面 | ワイヤーフレーム | 実装 |
| 会話ログ・テキスト速度/文字サイズ | 検討（設計のみ） | 実装 |
| オート・スキップ・クイックジャンプ | 対象外 | イベントが増えたら |
| ボイス・音量・ボイス再生 | 対象外 | 音声導入時 |
| CG回想・シーン選択・スクリーンショット | 対象外 | 作品ボリュームに応じて |

## 4. 見た目の方向性（未確定）
- 常駐中は最小限の装飾。立ち絵の存在感を最優先。
- イベント画面のテキストボックスには半透明パネルなどを用い、背景と文字のコントラストを確保。
- ボタンは「文字＋アイコン」の併記を基本。
- 色・ロゴ・形状・イラストは本作独自のデザインにする。
- 他作品の画面画像、ボタン素材、商標、UIアセットをコピーしない。
- 文字サイズ、行間、マルチモニター/DPIでの見やすさを確認。

## 5. 操作・遷移
```text
起動 → 日常モード
  ├─ キャラをクリック → 表情変更 + 吹き出し
  ├─ キャラをドラッグ → 位置変更（保存）
  ├─ 右クリック → コンテキストメニュー
  │   ├─ 交流を開く → 交流・イベントモード（将来）
  │   ├─ 設定 → 設定ウィンドウ
  │   ├─ 非表示
  │   └─ 終了
  └─ トレイ → 表示/非表示、設定、終了

交流・イベントモード
  ├─ 会話を進める
  ├─ ログを見る（将来）
  ├─ 設定（将来）
  └─ 戻る → 日常モード
```

## 6. 受け入れ基準（UI設計）
- 日常モードの画面が、通常のPC作業を妨げない
- 表情・吹き出し・設定への導線が分かる
- マウス右クリック・ドラッグ・クリックが衝突しない
- 設定・非表示・終了の方法が分かる
- イベント画面は日常モードと役割を明確に分離できる
- 他社UIの模倣ではなく、参考記事の機能設計を本作向けに再解釈できている
