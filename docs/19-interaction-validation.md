# MVP-06 クリック交流・表情リアクションの検証

## 実装範囲

キャラの有効画素上で左ボタンを押し、ドラッグせず有効画素上で離したときだけ交流する。DOM の click イベントは別途利用しないため、pointerup と click の二重発火はしない。透明部、右クリック、キャンセル、ドラッグ終了では反応しない。

短いセリフと表情は行動別に各3種類（合計12種類）。直前に選んだ同じ行動のセリフを次回の候補から外し、ランダム選択する。

| 行動 | セリフ例 | 表情方針 | 受付間隔 |
| --- | --- | --- | --- |
| idle | やっほー！ / んー、今日は何しよっかな？ | smile / surprised | 3秒 |
| reading | この本、おもしろいんだよ！ | smile / neutral | 3秒 |
| resting | ふぅ〜、休憩しよっ！ | smile / neutral | 3秒 |
| sleeping | んん……おやすみ…… | sleepy のまま | 15秒 |

表情と吹き出しは3秒で戻る。睡眠中も行動エンジンを起こしたり停止したりしない。間隔内の連打は表示・音・タイマー・通知を増やさない。音声は今回追加していない。受付間隔は全行動で共有し、途中で行動が変わっても前の受付期限を維持する。

小春の初期の明るい口調を使用し、好感度による照れ・甘えは #7 に残す。好感度、交流回数の保存、正式な小春画像への切替、Live2D は追加していない。既存ランタイムの画像とフォールバックを使い、新規依存・画像・音声素材なし。

## 入力の判定

`PointerGesture` は UI なしでテストできる。開始/終了のアルファヒット、左ボタン、pointerId を確認し、移動とキャンセルを追跡する。ウィンドウ移動で変化する client 座標を移動量に使わない。

- Main は従来どおり `screen.getCursorScreenPoint()` の DIP で6 DIPの移動を判定する。
- 新しい `finishDrag()` は最後にもカーソルを採取し、click / drag / cancelled のどれかだけを返す。16msの監視より短いドラッグも終了時の変位で拾う。
- 画面端でウィンドウを動かせなくても、Main が移動ありと判断すれば交流しない。
- Renderer も screen 座標の最大変位を追い、6以上移動して元に戻る経路を保守的にドラッグ扱いにする。混在DPI環境でこの補助判定が厳しめになる可能性は残る。
- 終了のIPC応答を待つ間は新しいジェスチャーを開始しない。blur、pointercancel、予期しないcapture喪失、非表示、右クリック、スリープ、pagehideでキャンセルし、遅れて返った応答から反応しない。
- 自分で正常終了後にcaptureを解放した場合の lostpointercapture はキャンセルと区別する。

finishDrag は送信元ウィンドウ/メインフレームを検証する。公開する結果は分類文字列のみで、座標・任意IPC・ファイルアクセスは公開しない。ドラッグ監視の30秒安全停止も単調時計を使用する。

## 描画と行動の分離

`InteractionRenderer` は `CharacterRenderer` を包み、PNG DOM に依存しない。自律行動や開発プレビューからの最新状態を保持し、反応中だけ表情を重ねる。3秒後は開始時の古い状態ではなく最新の通常状態へ戻す。

途中で行動そのものが変わったら、その時点で古い反応と吹き出しを取り消し、新しい行動へ描画を渡す。非表示/スリープでも一時反応を取り消す。タイマーは世代番号で古い復元を拒否し、dispose は二重に呼んでも本体を二重解放しない。

受け付けた反応だけを Renderer 内の `character-interaction` CustomEvent で通知する。detail は action / id / text / expression。ドラッグや受付間隔内のクリックでは通知しない。#7 の関係性処理は後からこの通知を利用できる。

## 吹き出しと作業への配慮

起動/時刻挨拶とクリック反応は同じ短い吹き出しを使う。クリック反応中は受動的な挨拶を上書きさせない。吹き出しは引き続き pointer-events:none で、キャラのヒット領域やウィンドウ寸法を増やさない。

自律遷移ごとのひとり言や定期的な自発吹き出しは追加しない。初回/起動挨拶は従来どおり1回表示し、復帰時の受動的な挨拶はアプリ自身が可視かつフォーカス中の場合だけ表示する。作業内容、他アプリ名、画面、キー入力は取得しない。詳しいひとり言設定は #9。

## 自動検証（ローカル macOS）

- `npm run check`: ESLint / Prettier / 単体テスト43件 / 型チェック / ビルド成功。
- 交流用11件で、短いクリック1回、透明部/右ボタン0回、ドラッグ往復/高速移動/画面端の抑制、異なるpointerId、キャンセル・遅延IPC・失敗、12種の応答、連打、睡眠、最新状態への復元、優先度、解放を検証。
- `npm run test:smoke`: 本物の Electron Renderer に mouseDown / mouseMove / mouseUp を送出し、透明部→ドラッグ→キャンセル→右クリックを先に試して交流0回、その後の短いクリックで1回、連打で増えないことを確認。先にクリックしてクールダウンが不正なドラッグ反応を隠すテストにはしていない。
- Main の DIP カーソルを模擬して、移動・停止・最後の採取による高速ドラッグ検出と cancelled 結果も確認。既存トレイ/最前面/透過/位置復旧/終了も成功。
- `npm run test:character`: 実 PNG の画像が反応中だけ変わり、時間後に元の画像へ戻ること、吹き出しと受け付けた通知が1回であることを確認。既存の状態・時間帯・欠損・アルファ判定テストも成功。

[Electron の sendInputEvent](https://www.electronjs.org/docs/latest/api/web-contents#contentssendinputeventinputevent) はフォーカスが必要なため、smoke は検証ウィンドウをフォーカスして実行する。これは OS 越しの実マウスや別アプリへのクリック到達を証明するテストではない。macOS / Windows CI で同じ検証を実行する。

## 手動確認（未実施）

1. `npm run dev`。キャラを短く左クリックして、吹き出しと表情が1回出て約3秒で戻ることを確認。
2. キャラをドラッグして離し、移動だけで吹き出しが出ないことを確認。画面端、元の位置へ戻すドラッグ、素早いドラッグも試す。
3. 透明な角・脚の間は反応0回、右クリックはメニューだけであることを確認。クリック透過OFFでも同じ条件を確認。
4. 連打しても吹き出しが積み重ならず、タイマーを延長し続けないことを確認。
5. 行動別のテストはConsoleで `behaviorPreview.pause()` の後、次を順に設定して実クリックする。通常は3秒以上、睡眠の反応後は15秒以上あける。

```js
await characterPreview.setState({ action: 'idle', expression: 'neutral' })
await characterPreview.setState({ action: 'reading', expression: 'neutral' })
await characterPreview.setState({ action: 'sleeping', expression: 'sleepy' })
```

6. 睡眠では起きず、眠そうな反応が控えめに出ることを確認。自律動作へ戻す場合は `behaviorPreview.resume()`（次の遷移で行動表示を更新）。
7. 反応中の非表示/再表示、右クリック、最前面切替、位置リセット、終了を確認。別アプリで作業中のスリープ復帰では自発的な挨拶を出さないことも確認。
8. Consoleで `addEventListener('character-interaction', e => console.log(e.detail))` を設定すると、受け付けた反応のみを確認できる。

実マウスの操作感、混在DPI、実スリープ、Retina/外部画面、Windows実機は未実施として残す。既存のOSクリック透過の制限も継続する。
