## 1. 状態と遷移図

画面状態（日常/一覧/再生/確認/補助）と、表示可否・停止理由・衣装を別に扱う。成人向けモードと衣装は独立。下図の「専用」は成人向け専用を指す。実線/点線で実装済みを区別する代わりに、各辺に【現行】【提案】を明示する。

```text
起動 / 再起動
  └─【現行】起動表示設定 ── ON → 日常（通常PNG、保存衣装※#37後）
                         └ OFF → 非表示・トレイ待機
日常 / 非表示
  ├─【現行】右クリック/トレイ → 設定 → 閉じる → 元の表示状態
  │                               ├─【提案 #37】衣装選択 → 日常へ適用
  │                               └─【提案 #29】専用入口 → 成人自己申告
  │                                         ├ キャンセル/Esc → 設定
  │                                         └ 明示確認 → 専用一覧
  ├─【提案 #30】お話・イベント… → 一般一覧 → 明示開始 → 一般再生
  ├─【現行】非表示 ←→ トレイで表示（フォーカスを奪わない）
  └─【現行】終了 → 保存 → プロセス終了

一般一覧 / 一般再生
  ├─【提案】ログ（#32）/ 設定 → 閉じる → 同じ位置（進行は停止）
  ├─【提案】戻る / Esc / OSウィンドウ閉じる / 完了 → 日常
  └─【提案】非表示 → 再生停止・中断位置保存 → 非表示・トレイ待機

専用一覧 / 専用再生 / 専用ログ / 専用ギャラリー（#33）
  ├─【提案】戻る / Esc / OSウィンドウ閉じる / 完了 → 通常の日常
  ├─【承認済み D5】フォーカス喪失
  │   ├ 自動非表示ON → 専用画面を隠す・進行停止（自動再表示しない）
  │   └ 自動非表示OFF → 表示維持可・進行一時停止（自動送りも停止）
  ├─【提案】明示的な非表示 → 専用状態解除 → 非表示・トレイ待機
  ├─【承認済み D5】OSスリープ → 設定に関係なく専用画面終了・通常モード
  ├─【提案】設定 → 専用状態解除 → 通常設定（専用画面を背後に残さない）
  └─【承認済み D5/D10】終了 / 再起動 → 専用画面を終了・通常モード
      （クラッシュ後も通常起動する設計）

専用からの退出・非表示・再起動後に続きへ進む場合
  設定の専用入口 → 成人自己申告を再確認 → 専用一覧 →「続きから」
  ※親密度・時刻・衣装・トレイ再表示・復帰通知だけでは専用へ戻らない。
```

一般イベントの一覧へ戻る「イベントを選び直す」は別ラベルとし、「日常へ戻る」と混同しない。専用状態で一覧へ戻る操作も可能だが、Escと「日常へ戻る」は常に通常へ離脱する。専用の全階層で共通にする。

### 1.1 D5/D10の境界と #29 との整合

**ユーザー承認済みのD5契約**は専用画面のblur時だけ設定で分岐すること。ONで非表示・自動再表示なし、OFFで表示維持可・進行休止。OSスリープ・終了・再起動はON/OFFを無視して専用を終了し通常へ戻す。単なるフォーカス再取得とOS復帰を区別し、OFFの表示維持を「専用画面を自動再起動する」動作にしない。

初期値ONは推奨。設定ラベル・既存設定への追加位置・保存キー/旧データ既定値の詳細は #29 への補足提案であり、#9の作り直しはしない。ONで隠した後は専用状態を解除し、再表示は通常PNG、専用再開は入口の再確認と一覧の「続きから」を必要とする案を推奨する。OFFのフォーカス再取得でもauto/skipを勝手に再開せず、明示入力から再開する案。これらの追加詳細は承認範囲を広げず最終確認待ちとして扱う。

Issue #29本文を確認した時点ではフォーカス喪失の個別条項はなく、「初期状態・起動時・復帰時は必ず通常モード」という一般条項がある。後続実装では復帰をOSスリープ/アプリ再起動と、単なるblur→focusに分け、後者だけD5の設定分岐を適用する。この文書を #29 への引き渡し差分とし、今回GitHub Issue本文は変更しない。

**D10承認済み**：イベント進行時に中断位置を自動保存できる構造とし、戻る/閉じるでも安全に中断する。#30へはイベントID・ノードID・本文ページ・確定済み選択のチェックポイント候補を渡し、#8の保存経路を再利用する。確定前の選択を既成結果として保存しない。保存頻度・原子的更新・台本更新時の移行方式は実装設計で定める。保存失敗時は最後に保存できた位置からになると説明し、非表示/終了は待たせない。再開は一覧からの明示操作で、再起動後の成人イベントは必ず専用再入場・確認を通す。

### クリック透過とフォーカス（提案の境界）

- 日常はPNG alpha hitTestと既存の透過設定を維持。OFF時は透明領域が背後操作を遮るが、そこで交流・ドラッグ・キャラメニューを始めない。透過の切替と復旧はトレイに残す。
- イベント/確認/衣装/ログ/設定の操作面は矩形の通常ウィンドウとして入力を受け、日常のclickThrough設定を引き継がない。本文・選択肢のクリックが背後アプリへ届かないことを #29/#30 で検証する。
- 明示「開始」でイベント窓へフォーカス。一般画面のログ閉じる時は呼出元ボタン、選択確定後は次の本文、画像欠損時は代替本文へ移す。フォーカスを失っただけで選択確定しない。
- 日常復帰は既存showInactiveを基本とし他アプリのフォーカスを奪わない。専用の自己申告はキャンセルへ初期フォーカスし、ダイアログ内のTab循環を検証。専用設定ボタンは通常への離脱を伴うとラベル補足する。
- OSタイトルバーに出す名前は中立な「お話・イベント」。専用画像をサムネイル/通知へ自動登録しない。OS側のウィンドウプレビューや切替時の残像を含む露出防止は #29/#34 で実機確認が必要で、設計文書だけで保証しない。
