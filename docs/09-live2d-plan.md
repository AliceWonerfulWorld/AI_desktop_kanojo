# Live2D導入計画（理想形 / 技術検証先行）

> 2026-11-07: **Live2Dは実現したい理想**。ハッカソンの基本MVPはPNG仮素材でも成立させ、Live2Dの採用可否は検証結果で決める。

## 目的
キャラクターがデスクトップで生活している「存在感」を、2D立ち絵の自然な呼吸・まばたき・視線・表情・姿勢変化で高める。

## 採用候補
- Live2D Cubism SDK for Web（TypeScript / WebGL）。
- Electron Renderer上でWebGL描画を行う案を検証する。
- SDKの公式サンプルを参考にする。Cubism Coreなどのライセンス対象物は利用規約を確認して取得・再配布する。

公式:
- https://www.live2d.com/sdk/about/
- https://www.live2d.com/sdk/download/web/
- https://docs.live2d.com/cubism-sdk-manual/cubism-sdk-for-web/
- https://www.live2d.com/sdk/license/

## 開発段階
### 1. 表示インターフェースの分離（MVP初期）
- 行動ロジックが直接PNG DOMやLive2D APIを呼ばない。
- `Action` / `Expression` 等、描画方式に依存しない意味データを渡す。
- 最初は`PngCharacterRenderer`等で仮素材を表示。
- 描画インターフェースの名称・型・配置は実装時にリポジトリの構成に合わせて決める。

### 2. Cubism表示技術検証（優先拡張）
- ライセンス上使用可能なサンプルモデルを用意し、Electron Rendererで表示。
- 透明ウィンドウでモデル・アルファ・WebGLを動作確認。
- PNG版と同じキャラの表示領域を用いる。
- まばたき / 呼吸 / 表情変更 / 簡単なモーションを確認。
- マウスクリックとドラッグ、透明領域のヒットテストを評価。
- CPU/GPU/メモリ負荷やスリープ復帰を計測・記録。
- 重大な制限や権利上の問題があればPNG版を残す。

### 3. 行動エンジンとLive2Dを統合（検証成功後）
- `idle` / `reading` / `resting` / `sleeping` にモーションを割り当てる。
- 状態遷移時の動作の中断・合成・優先順位を制御。
- タスクトレイ非表示中の描画更新を抑制。
- 交流による表情・モーション変化を実装。
- セーブデータを描画方式に依存させない。

## リスク
- モデル制作（パーツ分け・リギング・モーション制作）の工数が大きい。
- WebGL透明とOSレベルのクリック透過は別問題。
- ネイティブウィンドウの透過・DPI・GPU環境による描画差。
- Live2D Cubism Editorの利用条件、モデル使用権、Cubism SDK / Coreの再配布条件。
- **販売時にはLive2Dの「拡張性アプリケーション」該当性を含め出版許諾要件を公式で確認。** 個人・小規模でも免除の例外があるため断定しない。

## 実装しないこと（技術検証中）
- 本番のオリジナルモデル制作を自動生成すること
- ライセンス不明なモデル/SDK/Coreのリポジトリ同梱
- AI会話、音声認識、ネット通信、成人向けイベント
- 既存のPNG描画やデスクトップ操作の無断削除

## 検証成功条件
- Electron上で指定モデルを安定描画し、背景透明を維持。
- モデルの表情変化、まばたき、呼吸を確認。
- PNG版の行動エンジン・セーブ形式を壊さない。
- Windowsで負荷と操作性の測定結果を残す。
- 販売に向けたライセンス課題をドキュメント化する。
